这个网站就是 JM/OS：一个在浏览器里运行的 Mac OS X 风格桌面。我的简历、项目和照片都是可以从 Dock 打开的应用。围绕它们的是一个真正能用的桌面：窗口可以拖动、叠放、用神灯效果最小化、用 Exposé 铺开，还有 Spotlight、Dashboard 和屏幕保护程序。也有和此刻在线的其他访客一起玩的东西：聊天室、留言板，以及访客之间的 AirDrop。

它的起点是 [ryOS](https://github.com/ryokun6/ryos)，图标、字体和桌面图片都来自它。其余部分都是为这个网站写的，以 AGPL 开源。

## 怎么搭的

整个页面是一个 Astro 路由，里面只有一个 React island。所有内容都在构建时组装好：文字、项目页，以及我 Unsplash 照片的快照。没有 JavaScript 的访客和爬虫拿到的是同样内容的纯 HTML。

- **窗口管理**是一个很小的 zustand store：一张窗口表加一个层叠顺序。窗口按打开顺序渲染、用 `z-index` 叠放，因为移动 DOM 节点会让内嵌视频重新加载。
- **应用即数据。**每个应用是注册表里的一条记录：名字、图标、尺寸、出现在哪里，以及懒加载的组件。Dock、Spotlight、终端、Finder 和 `/?open=` 链接都读它，所以加一个应用只需要加一条记录。
- **每个窗口相互隔离。**某个应用出错，或者部署后它的代码已经不在了，只有它自己的窗口会显示错误，桌面其余部分照常工作。
- **桌面跟随访客所在的地方。**天空按访客当地的时间和天气给壁纸着色；强调色从桌面图片里取样；菜单栏文字根据背后的画面自动变白或变黑。

## 后端

账号、聊天室、留言板和在线状态都跑在 Supabase 上。浏览器只持有公开密钥，所有规则都由数据库执行：

- 每张表都有行级安全策略和列级授权；
- 私密数据（找回邮箱、重置令牌）放在 API 访问不到的 schema 里；
- 按成员计的限额（每天三条留言、聊天防刷屏）会先拿一把 advisory lock。在此之前，同时发出的六条留言全都通过了「每天三条」的检查。

一套测试在 CI 里用真实的 Postgres 检查大约五十条这样的规则，并用并发会话对每个限额做竞态测试。新的留言和消息会通过 Telegram 发给我，附带隐藏按钮；同一个 bot 也负责发布我的 Soapbox 帖子。

## 性能

装满应用的桌面，加载起来依然可以像一个网页：

- 首次访问约 125 KB JavaScript（gzip 后），每个应用只在打开时才加载；
- 图片 0.95 MB，原来是 2.2 MB——后来发现桌面图片被下载了两次；
- 开着六个应用拖动窗口，脚本耗时从 640 ms 降到 210 ms，因为现在只有被拖动的窗口会重新渲染。

这些都是预算，`npm run perf` 会在真实浏览器里检查。

## 测试

每个 pull request 都会做类型检查、单元测试和构建，然后用浏览器把生产构建里的每个应用都打开一遍，出现任何错误就失败。游戏规则（蜘蛛纸牌，以及由机器人来打的弹球台）和 Telegram bot 也有各自的单元测试。
